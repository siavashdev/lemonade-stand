# v0.12.0

_Release date: 2026-11-13_

Compatibility with Lemonade Server v2026.46.2, plus in-app diagnostics for both the server and Lemonade Stand.

## Added
- **Separate log viewers** under the hamburger menu for the Lemonade server and Lemonade Stand itself.
- Search, severity filters, live follow, copy, clear, connection status, and access to the optional on-disk app log.
- **More scheduled-task triggers** ([#45](https://github.com/siavashdev/lemonade-stand/issues/45)): besides "Daily at" and "When the app opens", a Pitcher can now run **weekly** on chosen weekdays (including Mon-Fri), **monthly** on a day of the month, or at a fixed **interval** (every 15 minutes to 24 hours) while the app is open. Weekly and monthly tasks catch up on launch like daily ones, and you can ask for them from chat (e.g. "every Monday at 9").
- **Word Documents** in the Pantry: the agent can turn Markdown it writes into a Word (`.docx`) document with headings, lists, tables, links, and code blocks. It is bundled with the app, so it works offline with no Node, Python, or Word install. It is create-only: it never overwrites an existing file unless asked, and it only writes `.docx` files, so tell the agent where to save (for example a folder the Filesystem tool can access). Powered by [markdown-to-word](https://github.com/benbalter/markdown-to-word-js).

## Changed
- Bundled npm-based tools now launch correctly on the app's built-in Node even when their command-line parser treats Electron as an app host, which would otherwise fail with "too many arguments".
- Added `markdown-to-word` as a bundled dependency (added 50 MB).
- Updated the documented Docker setup to persist all current Lemonade server data and configuration volumes.
- Expanded model classification for the latest server labels, including transcription, image, audio, embedding, reranking, and classification models.
- Updated Electron, OpenAI, MCP, sanitization, and build dependencies to patched releases; the release audit reports no known vulnerabilities.

## Fixed
- Omni collections now preflight their component downloads and explain missing components instead of returning a cryptic chat response.
- Omni chat failures delivered as normal assistant text are now surfaced as real, actionable errors.
- Omni collections load their LLM component with the requested context size instead of silently running at 4096 tokens.
- Fully installed Omni collections remain available when the server incorrectly flips the collection's own `downloaded` flag to false.
- Dictation only selects an already-downloaded speech-to-text model, preventing an unexpected model download and apparent hang.
- A slow startup model load can no longer override a newer model selected by the user.
- Server log streams stop cleanly when the window reloads or exits, and clearing a viewer also discards queued lines.
- MCP integration tests for time, SQLite, Git, and fetch servers now check the tool response's text field instead of treating the entire response as a string.
- Newly added SQLite tools start again. The archived SQLite server crashes on launch with the MCP Python SDK 2.x that `uvx` now resolves by default, so the Pantry pins the SDK to 1.x for it.
- Production builds no longer fail on the scheduler's shared-code import, so packaged installers build again.

## Security
- Updated Mermaid's KaTeX dependency to 0.18.2 to prevent inherited renderer settings from bypassing trust restrictions when prototypes are already polluted ([GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7)).
- Pinned affected minimatch dependencies to 11.0.8 to address glob-pattern denial of service, while preserving the older APIs required by packaging tools ([GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)).

## Known issues
- Audio data URLs returned directly inside an Omni assistant reply are not yet extracted into a playable audio artifact.
- A SQLite tool added before this release keeps its old launch arguments. If it fails to start, remove it in the Pantry and add it again to pick up the fix.
